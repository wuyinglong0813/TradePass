## 用户可走通的主流程

1. 登录，必要时在手机微信补绑手机号，完成个人实名认证。
2. 创建企业并完成企业认证；法人本人激活法人，经办人激活管理员。
3. 经办人企业邀请法人加入，法人本人完成法人身份核验，再分配采购、销售、财务等业务角色。
4. 建立企业合作关系，设置电子印章，创建合同。
5. 发起方先签，对方随后签署；首页和签署中心提示当前需要本方处理的任务。
6. 办理销售/退货单据、接收和入库，上传和确认凭证、发票；财务查看其有权访问的资料。
7. 处理完草稿、待确认、驳回和待入库资料后，双方确认结束合同。
8. 如需作废，双方先确认，再完成外部作废协议签署；若作废中止，双方申请恢复，经系统确认外部协议未生效且任务停止后继续履约。

## 发布前真实服务验收

本次新增 V33–V36：企业认证恢复字段、已取消作废任务留痕、手机号查询索引和作废创建意图。先迁移再启动新后端，并配套发布小程序。迁移不批量更改历史用户角色和业务单据。

- 用法人、授权代理人两个不同的实名账号分别走企业认证，核对 SDK 返回的 operatorType、operatorId 与本账号 verifiedOpenUserId 对应关系。
- 从代理人创建的企业邀请法人加入，验证第三方企业身份变更页面支持由法人本人完成此次核验，并能正确返回商签通。
- 用测试合同走双方顺序签署，再走作废协议停止及恢复；覆盖取消请求超时和迟到回调。外部状态不确定时保持冻结并核实，不通过清除本地记录强行恢复。
- 手机微信授权绑定手机号；电脑与手机使用同一微信账号继续个人认证，确认不生成重复账号。
- 运行 `npm test` 和 `mvn -f backend/pom.xml test`，数据库并发用例还需隔离测试数据库。测试日志与具体结果以本次实际执行为准。

历史上误授予的法人身份不会被批量降权；已签署合同的档案不自动改写。此类历史数据需要真实认证证据单独处理。
